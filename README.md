# 화면 공유 도구 모음 (ScreenShareSuite)

LAN/인터넷에서 다른 PC의 화면을 **보고, 마우스·키보드로 조작하고, 파일을 주고받는** 통합 프로그램입니다.
**DLL 없이 단일 실행파일**(`ScreenShareSuite.exe`) 하나로 동작하며, 런처 화면에서 버튼으로 기능 창을 띄웁니다.

> ✅ 빌드·동작 검증 완료 — TLS(AES256), 비밀번호 인증, 멀티 모니터, 원격 제어, 서버 종료 감지, 양방향 파일 전송까지 확인.

## ▶ 실행 / 런처

`ScreenShareSuite.exe` 를 실행하면 **런처 창**이 뜹니다. 두 개의 버튼이 있습니다.

| 버튼 | 역할 |
|------|------|
| **서버 — 내 화면 송출 / 원격 피제어** | 내 화면을 다른 PC가 보고 조작하도록 송출 (호스트) |
| **클라이언트 — 상대 화면 보기 / 원격 제어** | 다른 PC에 접속해 화면을 보고 조작 (뷰어) |

- **서버**·**클라이언트** 창은 각각 독립적으로 동작합니다.
- 서버 창은 **하나만**(이미 열려 있으면 앞으로 가져옴), 클라이언트 창은 **여러 개** 띄울 수 있습니다.
- 런처 창을 닫으면 모든 창이 함께 종료됩니다.
- 양방향으로 쓰려면 두 PC 모두 이 프로그램을 실행하고, 서로 상대 서버에 클라이언트로 접속하면 됩니다.

## 🖥 서버 창 (송출 / 피제어)

창을 열면 자동으로 송출이 시작됩니다.

| 항목 | 설명 |
|------|------|
| **내 주소** | 상단에 내부망 IP(같은 공유기) + 외부망(UPnP) 주소가 표시됨. 상대에게 알려주세요. |
| **포트** | 기본 `5900`. 양쪽 동일해야 함. |
| **내 비밀번호** | 내 화면을 보려면 상대가 입력해야 하는 비밀번호. **설정 권장.** |
| **FPS / 화질** | 전송 속도·품질 (네트워크가 느리면 낮게). |
| **원격조작 허용** | 체크 시 상대가 내 PC를 조작 가능. 해제하면 화면만 공유(조작 차단). |
| **파일 보내기** | 접속 중인 클라이언트에게 파일 전송. |
| **주소 복사** | 내 접속 주소(내부망 IP + 외부망 IP, 포트 포함)를 클립보드에 복사 → 클라이언트에게 붙여넣어 전달. |
| **시작 / 중지** | 송출 시작·중지. |
| 하단 **로그** | 접속·인증·파일 송수신 등 이벤트 기록. |

### 원격 조작 표시
다른 PC가 내 PC를 조작하는 동안:
- 화면 상단에 **"⚠ 원격 조작 중 · (상대 주소)"** 빨간 배너 표시
- 조작 중인 마우스 커서 주위에 **노랑/빨강 강조 링** 표시

(둘 다 클릭이 통과되어 실제 조작을 방해하지 않습니다.)

## 👁 클라이언트 창 (보기 / 제어)

| 항목 | 설명 |
|------|------|
| **상대 IP / 포트 / 접속 비번** | 상대 서버 주소와 비밀번호 입력 후 **접속**. |
| **모니터** | 상대가 모니터 여러 대면 볼 화면 선택 (+ "전체 화면"). |
| **원격 제어 OFF→ON** | ON(빨강)으로 바꾸면 이 창의 마우스·키보드가 상대 PC로 전달됨. |
| **파일 보내기** | 서버(상대 PC)로 파일 전송. |
| **끊기** | 보기 종료. |

### 서버 종료 감지
서버가 꺼지거나 네트워크가 끊기면 화면에 **"⚠ 서버 연결이 종료되었습니다"** 가 크게 표시되고 작업표시줄이 깜빡입니다. (내가 직접 끊은 경우와 구분 표시)

## 📂 파일 주고받기 (양방향)

- **보내기**: 서버·클라이언트 양쪽 모두 `파일 보내기` 버튼으로 상대에게 파일 전송.
- **받기**: 받은 파일은 자동으로 **바탕화면**에 저장됩니다.
  - 클라이언트는 수신 완료 시 저장 경로를 알림 팝업으로 표시
  - 서버는 로그에 저장 경로 표시
- 같은 이름 파일이 있으면 `이름 (1).확장자` 처럼 자동으로 새 이름이 붙습니다.
- 전송은 화면 영상과 같은 암호화 통로를 공유하므로, 큰 파일 전송 중에는 화면이 잠시 느려질 수 있습니다.

---

## 🔒 보안

- **암호화**: 접속 즉시 **TLS 1.2** → 모든 화면·입력·파일이 **AES256**으로 암호화. 서버가 자체서명 인증서를 런타임 생성.
- **비밀번호**: **HMAC-SHA256 챌린지/응답** — 비밀번호 원문은 네트워크로 전송되지 않음. 틀리면 즉시 차단.
- **파일명 정화**: 받는 파일은 경로 탈출(`..\`)을 막고 파일명만 사용, 저장 위치는 받는 쪽 PC의 바탕화면으로 고정.
- 자체서명 인증서라 서버 신원까지 보증하진 않지만(중간자 방지 X), 전송 암호화 + 비밀번호로 사내 신뢰망에서 충분히 안전합니다.

## 🌐 네트워크 (같은 공유기 / 다른 공유기)

- **같은 공유기(같은 사무실 LAN)**: 추가 설정 없이 서버의 **내부망 IP**(예 `192.168.x.x`)로 바로 접속.
- **다른 장소/공유기(인터넷)**:
  - 서버가 켜질 때 **UPnP 자동 포트포워딩**을 시도하고, 성공하면 **공인 IP**를 표시 → 그 주소로 접속.
  - UPnP가 막혀 있으면 서버 로그의 안내대로 공유기 **수동 포트포워딩**(외부포트 5900 → 서버 내부IP:5900 TCP) 설정.
  - 공인 IP가 사설 대역(예 `100.64.x`)이면 **ISP 이중 NAT(CGNAT)** 로 외부 접속 불가 → VPN(Tailscale/ZeroTier 등) 권장.

### 방화벽
서버 PC 첫 실행 시 Windows 방화벽의 **[액세스 허용]** 을 누르세요. 안 되면 관리자 PowerShell:
```powershell
New-NetFirewallRule -DisplayName "ScreenShare 5900" -Direction Inbound -Action Allow -Protocol TCP -LocalPort 5900
```

## 🛠 직접 빌드

.NET **SDK 없이** Windows 내장 .NET Framework 4.8 컴파일러로 빌드합니다. (`System.Xml.dll` 은 UPnP XML 파싱에 필요)

```powershell
& "$env:WINDIR\Microsoft.NET\Framework64\v4.0.30319\csc.exe" /target:winexe `
  /out:ScreenShareSuite.exe `
  /reference:System.dll /reference:System.Core.dll `
  /reference:System.Drawing.dll /reference:System.Windows.Forms.dll /reference:System.Xml.dll `
  ScreenShareSuite.cs
```

> 단일 파일이므로 참조 DLL만 있으면 되고, 별도 라이브러리 산출물은 없습니다.
> 빌드 결과 `ScreenShareSuite.exe` 하나만 배포하면 동작합니다.

## 🔌 통신 프로토콜 (참고)

TLS 스트림 위에서 `[1바이트 type][4바이트 길이][payload]` 메시지를 주고받습니다.

| type | 방향 | 내용 |
|------|------|------|
| CHALLENGE | 서버→클라 | 인증용 난수(nonce) |
| AUTH | 클라→서버 | HMAC-SHA256(비밀번호, nonce) |
| AUTHOK / AUTHFAIL | 서버→클라 | 인증 성공(+모니터 목록) / 실패 |
| SELECT | 클라→서버 | 볼 모니터 index (-1=전체) |
| FRAME | 서버→클라 | JPEG 화면 |
| INPUT | 클라→서버 | 마우스/키보드 (정규화 좌표) |
| FILE_OFFER / FILE_CHUNK / FILE_END | 양방향 | 파일 메타 / 64KB 청크 / 완료 |

- 좌표는 0~1로 정규화 전송 → 받는 쪽이 선택 모니터 기준 실제 좌표로 환산해 `SendInput` 주입 (양쪽 해상도 달라도 정확).
- 서버는 화면 프레임과 파일 청크가 한 스트림을 공유하므로 `WriteLock` 으로 직렬화.
